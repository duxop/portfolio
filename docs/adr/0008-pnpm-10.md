## Context

On 2026-10-03 the newest pnpm is 12.8.1 (12.0.0 was released 2026-08-26), the newest 11.x is 11.28.2, and the newest 10.x is 10.34.6. The local machine has 11.18.0. Vercel's [Package Managers](https://vercel.com/docs/package-managers) page (last updated 2026-08-11) lists pnpm "6, 7, 8, 9, 10" as supported and picks the version from the lockfile. For anything newer, the documented route is Corepack: the `ENABLE_EXPERIMENTAL_COREPACK=1` env var plus the `packageManager` field ([Configuring a Build → Corepack](https://vercel.com/docs/builds/configure-a-build)). The same page says Corepack "is considered experimental".

## Options

### Option 1: pnpm 10.34.6, pinned in `packageManager`

- **Pros:** the newest version Vercel installs with zero config. Every other tool that installs pnpm reads the same field:
  - Turborepo supports "pnpm 8+" ([Support policy](https://turborepo.dev/docs/support-policy));
  - `pnpm/action-setup` reads `packageManager` when no version is given ([README](https://github.com/pnpm/action-setup));
  - a newer local pnpm "will automatically download and switch to the specified version" ([pnpm self-update](https://pnpm.io/9.x/cli/self-update)).
- **Cons:**
  - two majors behind the latest;
  - pnpm 11+ prefers `devEngines.packageManager` and calls `packageManager` legacy ([pnpm package.json](https://pnpm.io/package_json));
  - pnpm 11-only workspace settings aren't available.
- **Cost to reverse:** easy. Change one field and regenerate the lockfile.

### Option 2: pnpm 11.x, the version installed locally and used by clinicXpert

- **Pros:** matches the local machine and clinicXpert.
- **Cons:** on Vercel it needs the experimental Corepack env var on both projects. Without it, Vercel reads the lockfile and installs with pnpm 9 or 10 anyway.
- **Cost to reverse:** easy.

### Option 3: pnpm 12.8.1, the latest

- **Pros:** the newest.
- **Cons:** five weeks old. It needs the same Corepack route on Vercel, and Turborepo's support policy warns that new package-manager majors may not be supported right away.
- **Cost to reverse:** easy.

## Recommendation

Option 1. It's the newest version every place that runs an install (local, GitHub Actions, Vercel) supports without an experimental flag.

## Decision

Option 1, as recommended (2026-10-03).

## Consequences

- The root `package.json` has `"packageManager": "pnpm@10.34.6"`, and no `devEngines.packageManager`. On this machine, `pnpm` is Corepack's shim (Node 22 via nvm), which reads that field and runs exactly that version. It rejects a range: `pnpm init` wrote `^11.18.0`, and every `pnpm` command failed with "expected a semver version".
- CI's `pnpm/action-setup` step leaves out `version`, so the pin lives in one place.
- No Corepack env var on Vercel.
- `CLAUDE.md`'s "latest stable versions" rule now has two pinned exceptions: TypeScript (ADR 0005) and pnpm.

## Revisit when

Vercel's Package Managers page lists pnpm 11 or later.
